# Contributing

Thanks for your interest in contributing to this Terraform module. Please read
this guide before opening an issue or pull request, and be aware of the
[Code of Conduct](CODE_OF_CONDUCT.md).

## Scope

This module wraps the `goauthentik/authentik` Terraform provider for managing a
single Authentik **application** per invocation, supporting every provider
protocol (OAuth2, SAML, proxy, LDAP, RADIUS, WS-Federation, Microsoft Entra,
Google Workspace, RAC, SSF) with optional SCIM backchannel provisioning. See the
[README](README.md) for the full interface.

## Reporting Issues

### Bugs

Open an issue using the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md)
and include:

- Module version and Terraform/OpenTofu version
- Provider version and Authentik server version
- The protocol in use and a minimal reproduction (`plan` output, errors)
- Whether it reproduces against `main`

A `plan`/`apply` requires a live Authentik instance — that's expected, not a bug.

### Feature requests

Open an issue using the [feature request template](.github/ISSUE_TEMPLATE/feature_request.md).
Describe the use case and, where relevant, the provider attributes it needs.
New `protocol` support or new inputs/outputs count as a **minor** version bump;
breaking changes are not accepted without a strong justification.

### Security

Do **not** open a public issue for security problems. Follow the process in
[SECURITY.md](SECURITY.md).

## Development Setup

- Install `prek` (`brew install prek`) and `terraform-docs`
  (`brew install terraform-docs`), then `prek install` to wire the hooks into
  every commit.
- This is a plain Terraform module; see the [Terragrunt](README.md#terragrunt)
  section if you consume it from `terragrunt.hcl`.

Run these in order before pushing:

```bash
terraform fmt -recursive
terraform validate
tflint
prek run --all-files   # trailing-whitespace/EOF/secret checks + fmt/validate/tflint/docs
```

CI runs these checks (via the `validate` workflow) with `prek` and OpenTofu.

## README.md

**Do not edit `README.md` by hand.** It is generated by terraform-docs from
`variables.tf`, `outputs.tf`, and `versions.tf`, plus the narrative sections in
`docs/header.md` and `docs/footer.md`. `README.md` is kept in sync by two
mechanisms:

- The `docs` workflow regenerates `README.md` on every PR using a pinned
  terraform-docs docker image (managed by Renovate) and pushes the result back
  to the branch.
- A local `terraform_docs` pre-commit hook regenerates it with your
  system-installed terraform-docs. If that version differs from the CI pin, the
  formatting may differ and CI will push its own formatting back — don't fight
  it.

Guidelines:

- Edit the source files, then regenerate with `terraform-docs markdown --config .terraform-docs.yml .`
- The `validate` workflow runs the remaining checks (`fmt`, `validate`, `tflint`)
  and skips `terraform_docs`, which is handled by the `docs` workflow.
- Keep examples (`examples/minimal`, `examples/complete`, `examples/advanced`)
  in sync with the interface.

## Branching and Versioning

- The module follows [Semantic Versioning](README.md#versioning): major for
  breaking interface changes, minor for backward-compatible additions, patch for
  bug fixes that don't change the interface.
- Cut releases from `main` after PRs merge; pushing a `vX.Y.Z` tag triggers the
  release workflow.
- When a feature needs newer Authentik provider attributes, raise the provider
  lower bound in `versions.tf` and mention the minimum Authentik version in the
  release notes.

## Pull Requests

- One logical change per PR; keep the diff focused.
- Use the [PR template](.github/PULL_REQUEST_TEMPLATE.md) and complete the
  verification checklist.
- If the PR or any commit is authored with AI assistance, label the PR
  `ai-authored` and add a `Co-authored-by: <tool> <email>` trailer naming the
  tool used. See [AGENTS.md](AGENTS.md#ai-authorship).
